## Plan d'Implémentation

### 🔧 Fix 1: Pollination (génération de cover) non fiable

**Problème racine :** Le flux de génération de cover est entièrement asynchrone et fire-and-forget. Il y a 3 chemins concurrents qui peuvent échouer silencieusement. De plus, `needsLoopCardCover()` retourne `true` même quand une cover Pollinations est déjà assignée, causant des backfills redondants.

**Corrections :**

1. **`Dashboard.tsx` (lignes 2023-2033)** : Remplacer `void consumeCoverPrefetch(...)` par un `await`. Si le prefetch n'est pas prêt, appeler `persistPollinationsCardCoverForLoop` en synchrone avant que le loop ne soit rendu dans le store.

2. **`coverArt.ts` - `needsLoopCardCover()`** : Modifier pour retourner `false` dès qu'UNE URL http valide est présente (pas seulement les URLs Storage Supabase). Condition : si `details.coverUrl` est une URL http valide → `needsLoopCardCover` = false (même si c'est une URL Pollinations directe).

3. **`loopCoverBackfill.ts`** : Augmenter `REPAIR_MAX_PER_SESSION` de 4 → 12 pour éviter que les nouvelles créations soient ignorées par la limite.
