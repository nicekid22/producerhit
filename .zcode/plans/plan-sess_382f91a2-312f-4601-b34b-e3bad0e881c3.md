# AXE A — Probe ACE + intégration des features

## A.1 — État des lieux confirmé

Notre integration ACE distante (api.acemusic.ai) utilise 3 endpoints :
- `POST /v1/chat/completions` (chat LLM → audio direct) — corps JSON (cf. `buildAceChatCompletionsHttpBody` dans `supabase/functions/_shared/aceSampleMode.ts:64`)
- `POST /v1/music/generate` (multipart, pour remix + voice clone) — `supabase/functions/_shared/generateLoopAceMain.ts:586`
- `POST /release_task` + `POST /query_result` (async jobs) — `generationJobUtils.ts:511` et `:180`/`:261`

On envoie aujourd'hui : `model, thinking, use_format, messages, lyrics, task_type=text2music, audio_config {instrumental, duration, bpm, key_scale, time_signature, vocal_language, format, audio_format, shift, inference_steps, seed, seeds, use_random_seed}, sample_mode, sample_query, batch_size, lm_negative_prompt (melody only), lm_cfg_scale (melody only)`.

## A.2 — Nouveau script de probe `scripts/probe-ace-features.mjs`

Inspiré de l'existant (`probe-ace-dual-batch.mjs`, `probe-ace-stems.mjs`). Conventions :
- Charge `.env` (parse manuel de `.env` comme `probe-ace-stems.mjs:10`).
- `apiKey` depuis `ACE_STEP_API_KEY` / `ACE_STEP_API_KEYS[0]`.
- baseUrl `https://api.acemusic.ai` (normalisé).
- Prompt constant : "modern 2026 dark trap instrumental beat, no vocals, BPM ~140, punchy", `lyrics: "[instrumental]"` → ~1 crédit par gén, durée 16s.
- `batch_size: 2` (gratuit côté ACE quand accepté) → enrobe 2 seeds dans la même gén.
- Helpers : `probeOnce(label, overrides)` qui étend le body baseline, fetch `/v1/chat/completions`, capture `(status, ms, textStatus, jsonPreview, returnedAudioCount, returnedFields)` puis log en JSONL `scripts/ace-features-probe-results.jsonl` pour analyse diff.
- succès condition = `status 200` + présence de `choices[0].message.audio[0]` (avec URL ou data:). échec = 400/422 → on log le message exact ACE (souvent liste les champs inconnus rejetés).

Tests séquentiels (paramètres prioritaires) sur `/v1/chat/completions` :
1. baseline (control)
2. `+ audio_config.guidance_scale = 7.0`
3. `+ audio_config.inference_steps = 16` (vs 8 par défaut)
4. `+ audio_config.infer_method = "sde"`
5. `+ audio_config.infer_method = "ode"`
6. `+ audio_config.normalization_db = -14.0` + `enable_normalization: true`
7. `+ audio_config.latent_rescale = 0.92`
8. `+ audio_config.lm_temperature = 0.9, lm_top_k = 50, lm_top_p = 0.95`
9. `+ audio_config.cfg_interval_start = 0.0, cfg_interval_end = 0.7`
10. `auto_lrc = true` (top-level)
11. `auto_score = true, score_scale = 0.5`
12. `use_cot_metas = true, use_cot_caption = true, use_cot_language = true`
13. `parallel_thinking = true`
14. `track_name = "probe-test", complete_track_classes = ["trap"]`

Tests séparés sur `/v1/music/generate` (multipart) :
15. `task_type = "cover"` + source audio + `audio_cover_strength = 0.65` + `cover_noise_strength = 0.1` (cover flow natif)
16. `task_type = "repaint"` + `repainting_start = 0.25, repainting_end = 0.75` + `instruction = "..."` + source
17. `param_obj` via `/release_task` enrichi avec les champs 6-14 ci-dessus

Output : table markdown `scripts/ace-features-probe-report.md` auto-générée à la fin avec 3 colonnes (param, accepté, notes). C'est ce doc qui guidera l'intégration.
